# STEN Business Writing

## Назначение

Business Writing помогает управляющему подготовить служебную записку, ответ на письмо, протокол, недельный план, поручения менеджерам, сообщение команде, ответ гостю или письмо поставщику. Это provider-neutral слой подготовки задания, источникового контекста, редакторской проверки и структурированных черновиков задач.

## Основной принцип

Текст должен звучать как нормальная профессиональная коммуникация конкретного руководителя. Он не должен автоматически начинаться с «Уважаемые коллеги», состоять из одинаковых абзацев или завершаться пустой формулой вежливости. Стиль зависит от автора, адресата, цели, канала и ситуации.

Естественность достигается уместным содержанием и редактурой, а не искусственными ошибками, маскировкой происхождения текста или попытками обмануть AI-детекторы.

## Поддерживаемые типы

- `memo` — служебная/докладная записка;
- `email_reply` — ответ на письмо;
- `meeting_minutes` — протокол совещания;
- `weekly_plan` — план на неделю;
- `manager_tasks` — поручения менеджерам;
- `team_message` — сообщение команде;
- `guest_response` — ответ гостю;
- `supplier_letter` — письмо поставщику;
- `report` и `other` — прочие рабочие документы.

Каналы: `internal_chat`, `email`, `document`, `meeting`, `task_board`.

## Runtime API

```js
import { createWritingBrief, buildWritingPrompt, reviewWritingDraft, createManagerTaskDraft, checkEmailSenderReadiness } from "./src/writing/index.js";

const brief = createWritingBrief({
  request: "Подготовить сообщение менеджерам о незакрытых сменах",
  documentType: "team_message", channel: "internal_chat",
  authorRole: "управляющий", recipientRole: "менеджеры",
  facts: [{ id: "fact-1", statement: "Не все отчёты по закрытию смен поступили.", source: { type: "manager_input", id: "message-12" } }],
  unknowns: ["Причины отсутствия отчётов не установлены."],
  styleProfile: { formality: "деловой, прямой", length: "коротко" }
});
const prompt = buildWritingPrompt(brief);
// Передать prompt выбранной host/provider model для генерации текста.
const review = reviewWritingDraft({
  brief, draft: "Коллеги, не все отчёты по закрытию смен поступили.",
  claims: [{ text: "Не все отчёты поступили.", source_ids: ["fact-1"] }]
});
const task = createManagerTaskDraft({
  title: "Проверить закрытие смен", description: "Сверить отчёты и перечислить расхождения.",
  assignee: "Менеджер смены", dueDate: "2026-11-20",
  successCriteria: "Отчёты проверены, расхождения зафиксированы.", sourceRefs: ["message-12"]
});
```

## Как формируется текст

1. Определяется тип документа и канал.
2. Учитываются роль автора, адресат, цель и предпочтения стиля, если они известны.
3. В brief включаются только факты с идентификатором источника.
4. Неизвестное передаётся отдельно и не заполняется догадками.
5. Provider получает инструкцию писать естественно, конкретно и без универсальных шаблонов.
6. Проверяемые утверждения возвращаются вместе с source IDs.
7. Черновик проходит source-reference и editorial checks.
8. Человек утверждает итог перед отправкой или публикацией.

## Редакторская проверка

`reviewWritingDraft` проверяет структуру claims, наличие ссылок на известные fact IDs, неразрешённые плейсхолдеры и небольшой набор часто встречающихся канцелярских оборотов. Это вспомогательная проверка, не полноценное семантическое доказательство истинности текста. `ready_for_human_review` означает только прохождение встроенных проверок; документ всё равно требует человеческого просмотра.

## Поручения и планы

`createManagerTaskDraft` создаёт только черновик. Если не указаны ответственный, срок или критерий результата, поля остаются незаполненными и статус становится `needs_completion`. Функция не назначает задачу, не уведомляет менеджера и не меняет внешнюю систему.

Недельный план может быть подготовлен как документ или набор таких черновиков. Превращение его в реальные задачи требует отдельного host connector, полномочий и подтверждения.

## Email и антиспам

`checkEmailSenderReadiness` — предварительная проверка конфигурации отправителя. Она напоминает проверить SPF, DKIM и DMARC; для массовой отправки дополнительно проверяет подтверждение согласия адресатов, отписку и мониторинг жалоб. Она не анализирует «магические слова», не обещает прохождение спам-фильтров и не гарантирует попадание во входящие.

Репутация домена, аутентификация, качество списка получателей, жалобы, объём и характер рассылки зависят от реальной почтовой инфраструктуры и провайдера. Технические требования нужно сверять с актуальными правилами почтового сервиса.

## Ограничения

- Модуль не включает LLM и не генерирует текст самостоятельно: host/provider model выполняет генерацию по подготовленному brief.
- Нет подключения к Gmail/Outlook, отправки email, Telegram, CRM или task tracker.
- Нет автоматического обучения стилю и долговременного хранения предпочтений.
- Нет гарантии прохождения AI-детекторов или спам-фильтров.
- Нет автоматического назначения задач и уведомления сотрудников.
- Встроенные проверки не заменяют вычитку человеком и проверку первичных источников.
